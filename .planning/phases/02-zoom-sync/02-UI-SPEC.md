# Phase 2 — UI Design Contract: Zoom Sync

> Visual and interaction contract for Phase 2 (Zoom Sync) of the Tail History View.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> **Phase scope:** Two proof-of-concept charts (Latency, Packet Loss) rendered inside a new
> `ChartStrip` container. A `ZoomControls` row with an MUI Slider (read-only) and a "Reset Zoom"
> button. Synchronized zoom across both charts via `setExtremes` with feedback-loop guard.
> No real API data — mock data only. No chart interaction beyond zoom sync.
>
> **Contract rule:** This document EXTENDS the Phase 1 contract. Every value locked in Phase 1
> remains in force. Only new or Phase-2-specific additions are declared here.

## Spacing Scale

Unchanged from Phase 1. Reproduced here for executor reference.

| Token | Value | Usage in Phase 2 |
|-------|-------|------------------|
| xs | 4px | Icon gaps, chip padding |
| sm | 8px | ChartStrip internal top/bottom padding; ZoomControls row top/bottom padding |
| md | 16px | ChartStrip internal left/right padding; ZoomControls gap between slider and button |
| lg | 24px | ContentArea top/bottom padding (unchanged from Phase 1 shell) |
| xl | 32px | ContentArea left/right padding; ZoomControls row left/right padding |
| 2xl | 48px | Major section breaks (reserved) |
| 3xl | 64px | Page-level padding (reserved) |

Phase 2 exceptions:
- ChartStrip card padding: `8px 16px` (sm vertical, md horizontal) — asymmetric because the
  chart canvas extends to the inner edges; the title sits above the canvas within that same padding.
- ZoomControls row padding: `8px 32px` (sm vertical, xl horizontal) — matches ContentArea
  horizontal gutter so the slider aligns with chart left edges.
- MUI Slider thumb touch target: 40px (MUI v6 default) — not on the 8pt scale but satisfies
  WCAG 2.5.5. The slider is disabled in Phase 2 so the touch target is informational only.
- ChartStrip bottom margin: `16px` (md) — the gap between stacked chart strips.

## ChartStrip Anatomy

Precise visual specification for the `ChartStrip` component.

```
StripContainer (styled Box)
  width: 100%
  margin-bottom: 16px
  background-color: WHITE (#FFFFFF)
  border-radius: 4px
  border: 1px solid SURFACE_GREY[200] (#DEE4E8)
  padding: 8px 16px
  └── Typography variant="subtitle2" (14px/600/Source Sans Pro)
       gutterBottom: true (adds 0.35em bottom margin = ~5px)
       color: text.primary
       content: "{chart title}"
  └── StockChart container
       width: 100%
       height: {height}px  (default: 200px)
```

**No box-shadow on ChartStrip cards.** The border (1px SURFACE_GREY[200]) provides sufficient
card definition against the SURFACE_GREY[100] background without elevation. Adding a shadow here
would create visual hierarchy conflicts with the page header card (which has no shadow in
Phase 1). Consistent flat styling matches the Insights platform's analytics dashboard aesthetic.

**No chart legend.** `legend: {enabled: false}` in Highcharts options. With only one series per
PoC chart, a legend adds noise. Phase 3 will revisit per chart.

**No navigator, no scrollbar, no range selector.** These Highstock UI widgets are disabled
(`navigator: {enabled: false}`, `scrollbar: {enabled: false}`, `rangeSelector: {enabled: false}`).
The custom ZoomControls row serves as the zoom indicator; navigator would be redundant and would
fire conflicting `setExtremes` events.

**No built-in Highcharts "Reset Zoom" button.** Disabled via
`chart.zooming.resetButton: {theme: {display: 'none'}}`. The `ZoomControls` Reset Zoom button
provides this function across all charts simultaneously — the per-chart built-in button cannot
handle multi-chart reset and would produce inconsistent UX.

**No animation during zoom sync.** `chart.animation: false` in Highcharts options. When syncing
zoom across charts, animation is disabled so all charts snap to the new range simultaneously.
Animated transitions would make charts appear to lag behind the first chart, creating visual
inconsistency. This applies to the chart-level animation only; MUI component transitions are
unaffected.

## ZoomControls Anatomy

Precise visual specification for the `ZoomControls` component.

```
ControlsRow (styled Box)
  display: flex
  align-items: center
  gap: 16px
  padding: 8px 32px
  background: SURFACE_GREY[100] (inherited from page, no explicit bg needed)
  └── Slider (MUI v6)
       flex: 1  (takes all remaining width after the button)
       min: timeRange.start (epoch ms)
       max: timeRange.end (epoch ms)
       value: [zoomedRange.min, zoomedRange.max] OR [timeRange.start, timeRange.end]
       step: 60_000 (1-minute resolution)
       disabled: true  (Phase 2 — read-only indicator only)
       valueLabelDisplay: "off"  (no timestamp bubbles in Phase 2)
       data-testid: "zoom-slider"
  └── Button (MUI v6)
       variant: "outlined"
       size: "small"
       disabled: zoomedRange === null
       onClick: onResetZoom
       data-testid: "reset-zoom-button"
       label: "Reset Zoom"
```

**Slider visual states:**

| State | Condition | Visual |
|-------|-----------|--------|
| No zoom (full range) | `zoomedRange === null` | Slider track full-width, `disabled` styling — MUI grey (#00000042 / 12% black on both track and thumb). No colored fill because the thumb positions are at min/max. |
| Zoomed | `zoomedRange` is non-null | Slider track shows colored segment between the two thumbs, representing the zoomed window. Track fill color: PRIMARY_PURPLE (#724AE8) — MUI's default primary color for Slider. |

Note: MUI v6 Slider with `disabled` prop still renders the visual thumb positions and track
correctly, but prevents user interaction. The `disabled` styling applies a reduced-opacity
treatment to the thumb and active track. This is intentional in Phase 2 — it communicates that
the slider is a read-only indicator, not an interactive scrubber.

**"Reset Zoom" button states:**

| State | Condition | Visual |
|-------|-----------|--------|
| Inactive | `zoomedRange === null` | `disabled` — MUI disabled text (#00000042), no border highlight |
| Active | `zoomedRange` is non-null | Outlined button — border: 1px solid PRIMARY_PURPLE, text: PRIMARY_PURPLE, bg: transparent |

## Interaction Contract

### Zoom Interaction (ZOOM-01 + ZOOM-02)

| Event | Trigger | Result |
|-------|---------|--------|
| Drag-select on chart | User drags horizontally on any ChartStrip canvas | Highcharts fires `xAxis.events.setExtremes` with `e.trigger === 'zoom'`; `useChartSync` propagates to all other charts via `axis.setExtremes(min, max, true, false, {trigger: 'syncExtremes'})` |
| Zoom propagates to second chart | `setExtremes` with trigger `'syncExtremes'` fires on second chart | Guard `if (e.trigger === SYNC_TRIGGER) return` swallows the event immediately — no further propagation |
| Zoomed range written to store | Any user-initiated zoom | `setZoomedRange({min, max})` called on Zustand store; MUI Slider `value` updates to reflect new range |

**Cursor during drag:** Highcharts renders its own rubber-band selection box with a crosshair
cursor during drag-zoom. No custom cursor CSS is needed.

**Highcharts zoom reset button:** Hidden via `chart.zooming.resetButton: {theme: {display: 'none'}}`.
Users must use the `ZoomControls` Reset Zoom button.

### Reset Zoom Interaction (ZOOM-03 + ZOOM-04)

| Event | Trigger | Result |
|-------|---------|--------|
| Click "Reset Zoom" | Button is active (zoomedRange is non-null) | `resetZoom()` called: iterates registry, calls `axis.setExtremes(undefined, undefined, true, false, {trigger: 'syncExtremes'})` on all charts; calls `setZoomedRange(null)` on store |
| Slider returns to full range | `zoomedRange === null` in store | MUI Slider `value` reverts to `[timeRange.start, timeRange.end]`; thumb positions return to min/max |
| "Reset Zoom" button disables | `zoomedRange === null` | Button `disabled` prop becomes `true`; button is greyed out |

### Slider Interaction (Phase 2 — read-only)

The MUI Slider is `disabled` in Phase 2. Users cannot interact with it. It is a visual indicator
only. Interactive scrubbing (PLAY-01) is deferred to Phase 4.

## Copywriting Contract

Phase 2 introduces new interactive UI elements that need copy. Phase 1 copy is unchanged.

| Element | Copy | Notes |
|---------|------|-------|
| "Reset Zoom" button label | "Reset Zoom" | Two words, title case — matches Highcharts' built-in label convention and is immediately recognizable. Verb + noun pattern. |
| Slider aria-label | "Zoom range indicator" | Screen reader label for the disabled range slider. Communicates purpose without implying interactivity. |
| Slider aria-valuetext (when zoomed) | "{start date} to {end date}" | Formatted as ISO date strings or human-readable "May 1 to May 5" — to be determined in Phase 4 when slider becomes interactive. In Phase 2, omit `aria-valuetext` override; MUI Slider default is acceptable. |
| Chart title: Latency | "Latency" | Single word, no units in title. Units appear in y-axis label (ms). |
| Chart title: Packet Loss | "Packet Loss" | Two words, no units in title. Units appear in y-axis label (%). |
| Chart empty state (no data) | Not applicable in Phase 2 | Mock data always present; empty state defined in Phase 3. |
| Chart loading state | Not applicable in Phase 2 | No API calls; mock data is synchronous. |
| Chart error state | Not applicable in Phase 2 | No API calls in Phase 2. |

**Destructive actions in Phase 2:** none. "Reset Zoom" is a reversible state change — the user
can re-zoom at any time. No confirmation dialog is needed.

## Highcharts Chart Visual Contract

Visual settings applied to every `ChartStrip` instance via the `chartOptions` object. These
extend the global defaults set in Phase 1 `main.tsx`.

```typescript
// ChartStrip chartOptions — applied per instance
{
  chart: {
    height: 200,           // default; accepts height prop override
    zooming: {
      type: 'x',
      resetButton: {theme: {display: 'none'}}  // hide built-in button
    },
    animation: false,      // snap sync feels instant
    backgroundColor: 'transparent',  // inherits StripContainer WHITE bg
    style: {fontFamily: 'Source Sans Pro, sans-serif'}  // inherited from global, explicit here
  },
  xAxis: {
    type: 'datetime',
    // gridLineColor, lineColor, tickColor, label colors: inherited from Highcharts.setOptions() in main.tsx
    events: {setExtremes: onSetExtremes}  // sync handler injected per chart
  },
  yAxis: {title: {text: null}},  // no y-axis title; chart card title serves this purpose
  title: {text: null},           // no Highcharts title; Typography subtitle2 above canvas serves this
  credits: {enabled: false},
  legend: {enabled: false},
  navigator: {enabled: false},
  scrollbar: {enabled: false},
  rangeSelector: {enabled: false}
}
```

**Y-axis labels:** Inherit global default (12px, SURFACE_GREY[600]). No per-chart override in Phase 2.

**Tooltip:** Use Highcharts default tooltip. A custom tooltip design is deferred to Phase 3 when
real metric data with proper units arrives.

## Accessibility Contract

| Requirement | Implementation |
|-------------|----------------|
| "Reset Zoom" button keyboard accessible | MUI `Button` — inherits full keyboard focus; Enter/Space activates |
| Slider keyboard accessible | MUI `Slider` with `disabled` — keyboard interaction suppressed; screen reader announces it as a slider control with current value range |
| Slider aria-label | `aria-label="Zoom range indicator"` prop on `<Slider>` |
| ChartStrip chart canvas accessibility | Highcharts renders `<desc>` and `<title>` SVG elements by default; no override needed in Phase 2 |
| Color not sole differentiator | Slider state (zoomed vs not) is communicated by both track color AND button enabled/disabled state — not color alone |
| WCAG 2.5.5 touch targets | MUI Button `size="small"` renders at 30px height; the 32px horizontal gutter provides adequate spacing; acceptable for desktop-first analytics tool |
