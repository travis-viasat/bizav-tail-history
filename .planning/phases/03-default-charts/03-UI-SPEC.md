# Phase 3 — UI Design Contract: Default Charts

> Visual and interaction contract for Phase 3 (Default Charts) of the Tail History View.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> **Phase scope:** 8 default chart components added to `TailHistoryPage`. Each chart is a thin
> wrapper calling a typed mock hook and rendering through the existing `ChartStrip` component.
> All 8 charts participate in zoom sync via `useChartSync` + `chartRegistryRef`. `ChartStrip`
> receives three new optional props (`yAxisOptions`, `yAxisAdditional`, `legendEnabled`) added
> in a backward-compatible way. Loading (MUI Skeleton), empty, and error states are handled in
> each chart wrapper — NOT inside `ChartStrip`.
>
> **Contract rule:** This document EXTENDS the Phase 1 and Phase 2 contracts. Every value locked
> in those contracts remains in force. Only Phase-3-specific additions and overrides are declared
> here. When a value below says "unchanged from Phase N", go to that document for the full spec.

call in `main.tsx`. No new packages need to be installed.

Unchanged from Phase 1 and Phase 2. Reproduced here for executor reference.

| Token | Value | Usage in Phase 3 |
|-------|-------|-----------------|
| xs | 4px | Icon gaps, inline chip padding |
| sm | 8px | ChartStrip internal top/bottom padding; EmptyStripContainer top/bottom padding |
| md | 16px | ChartStrip internal left/right padding; EmptyStripContainer left/right padding; chart strip bottom margin |
| lg | 24px | ContentArea top/bottom padding (unchanged) |
| xl | 32px | ContentArea left/right padding; ZoomControls padding (unchanged) |
| 2xl | 48px | Reserved |
| 3xl | 64px | Reserved |

Phase 3 exceptions:
- Events Timeline chart height: 160px — shorter than the 200px standard because horizontal bars
  (x-range) need less vertical space than line plots. The height serves as a touch target for
  Highcharts zoom drag on the category axis.
- iQe Score chart height: 220px — taller than the 200px standard to accommodate the legend for
  8 line series without overlapping the chart canvas.
- All other 6 chart strips: 200px (the established Phase 2 default).
- MUI Skeleton `height` matches the chart height exactly for each chart — see Per-Chart Inventory.

Unchanged from Phase 1 and Phase 2. One new role used inside empty/error state containers.

| Role | Size | Weight | Line Height | Font | MUI Variant | Usage |
|------|------|--------|-------------|------|-------------|-------|
| Body | 16px | 400 (normal) | 1.5 | Source Sans Pro | body1 | General UI text |
| Label | 16px | 600 (semibold) | 1.0 | Source Sans Pro | label (custom) | Form labels |

**Two weights in use: 400 (normal) and 600 (semibold).** Unchanged.

**State Message** uses `variant="body2"` (14px/400) rendered in `color="text.secondary"` (70%
opacity of text.primary = #202E39B2). This is visually recessed relative to the chart title
(`subtitle2` at 600 weight), communicating that the message is a status placeholder, not content.

### New Optional Props Added to `ChartStripProps`

```typescript
// ChartStrip.types.ts additions — all optional; defaults preserve Phase 2 behavior
export interface ChartStripProps {
  // ... existing props unchanged ...

  /** Override the default single yAxis config. Used by Events Timeline for category axis. */
  yAxisOptions?: Highcharts.YAxisOptions;
  /** Additional yAxis instances appended after the primary. Used by Latency & Packet Loss for dual-axis. */

  legendEnabled?: boolean;
```

```typescript
yAxis: yAxisOptions ?? {title: {text: null}}
```

## Per-Chart Visual Contract

### CHART-01: Events Timeline

**Title text:** "Events Timeline"
**Height:** 160px
**Highcharts type:** `xrange` (module: `highcharts/modules/xrange`)
**Legend:** disabled (colorByPoint bars are self-explanatory; y-axis category labels serve as legend)

**yAxis configuration (passed via `yAxisOptions` prop):**
```
title: null
categories: ['Connected', 'Acquiring', 'Disconnected', 'Network Change', 'Timing Events']
reversed: false
min: 0
max: 4
```

**Bar appearance:**
- `borderRadius: 3` — slight rounding on bar ends
- `pointWidth: 20` — bar height in pixels (fits within 160px height with 5 categories)
- `colorByPoint: true` — each data point uses its own `color` field

**x-range data point shape:**
```typescript
{ x: startMs, x2: endMs, y: categoryIndex, color: tokenValue }
```

**Category index to color mapping:**

| y | Category | Color Token |
|---|----------|-------------|
| 0 | Connected | RAG_CONNECTED |
| 1 | Acquiring | RAG_ACQUIRING |
| 2 | Disconnected | RAG_DISCONNECTED |
| 3 | Network Change | SURFACE_GREY[600] |
| 4 | Timing Events | SURFACE_GREY[400] |

**Module initialization (in `main.tsx`, once before React renders):**
```typescript
import xrange from 'highcharts/modules/xrange';
import Highcharts from 'highcharts/highstock';
xrange(Highcharts); // alongside existing Highcharts.setOptions() call
```

## Loading State Contract (D-04)

**Trigger:** `isLoading === true` returned from mock hook.
**Component:** `MUI Skeleton` with `variant="rectangular"`, `width="100%"`, `animation="wave"`.

**Visual appearance:** The Skeleton is rendered inside an `EmptyStripContainer` that exactly
replicates `ChartStrip`'s `StripContainer` styling:

```
EmptyStripContainer (styled Box)
  width: 100%
  marginBottom: 16px        (md token)
  backgroundColor: WHITE
  borderRadius: 4px
  border: 1px solid SURFACE_GREY[200]
  padding: 8px 16px         (sm + md tokens)
  └── Skeleton
       variant: "rectangular"
       width: "100%"
       height: {CHART_HEIGHT}px  (matches the chart's height prop)
       animation: "wave"
```

**Height values by chart:**

| Chart | Skeleton Height |
|-------|----------------|
| CHART-01 Events Timeline | 160px |
| CHART-02 iQe Score | 220px |
| All others (CHART-03 through CHART-08 strips) | 200px |

**No layout shift:** The `EmptyStripContainer` occupies the exact same space as the rendered
`ChartStrip`. The skeleton transitions to the chart without any layout reflow.

**Simulated delay in mock hooks:** Each mock hook uses `useEffect` + `setTimeout` with a 400ms
delay before setting `isLoading: false`. This gives the skeleton time to render visibly in
development and confirms the loading state works correctly before real async data is wired.

## Error State Contract

**Trigger:** `error` is non-null (non-empty string) returned from mock hook. In Phase 3 this is
always `null` (mock hooks do not fail). The error state is defined now so the pattern exists when
real `useFetch` calls are introduced.

**Visual structure:** Identical to empty state, different message copy.

```
EmptyStripContainer
  └── Typography variant="subtitle2" gutterBottom   ← chart title
  └── Box (flex, center)
      └── Typography variant="body2" color="text.secondary"
          "Failed to load data."
```

**Copy (exact):** "Failed to load data."
- Same styling as empty state message.
- No retry button in Phase 3 — re-selecting the date range triggers a refetch.

**Priority order when multiple states are true:** `isLoading` > `error` > `isEmpty` > render chart.
```typescript
if (isLoading) return <Skeleton/>;
if (error) return <ErrorState/>;
if (isEmpty) return <EmptyState/>;
return <ChartStrip .../>;
```

## Interaction Contract

### Zoom Sync (all 8 charts, CHART-01 through CHART-08)

All Phase 3 charts participate in the existing zoom sync mechanism from Phase 2. No new
interaction contract is required — the `useChartSync` / `chartRegistryRef` pattern applies
identically to all chart types including x-range (CHART-01).

| Event | Result |
|-------|--------|
| User drags to zoom on any chart | All other charts snap to same range within one animation frame |
| User clicks "Reset Zoom" | All 10 strips return to full timeRange simultaneously |
| Date range changes | All mock hooks re-run (simulated via `useEffect` dependency on `timeRange`); loading skeletons appear, then charts re-render with data for the new range |

**Events Timeline zoom note:** The x-range chart type participates in Highcharts zoom via the
same `xAxis.events.setExtremes` mechanism as line charts. No special handling is required.
The x-axis is still a datetime axis — zoom ranges are still epoch ms values.

### Tooltip

Use Highcharts default tooltip for all charts in Phase 3. A custom tooltip with proper units
and formatting is deferred to a future enhancement. The default tooltip shows:
- x value: formatted as date/time (Highcharts datetime formatter)
- y value: the series value
- series name

**Exception — Events Timeline tooltip:** Highcharts x-range default tooltip shows the point's
`name` property if set. Set `name` on each data point to the human-readable state name (e.g.
"Connected", "Acquiring", "Disconnected") so the tooltip is useful without custom formatting.

### No Playback Crosshair in Phase 3

The synchronized crosshair (PLAY-05) is defined and built in Phase 4. Phase 3 charts do not
render a crosshair. The `playhead` slice in Zustand store is not read by any Phase 3 component.
